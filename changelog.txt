UNRELEASED

  - fix(security): a page on another site could consume an agent's unread
    mail by loading http://127.0.0.1:9480/inboxes/{agent} as an image
    (loopback Host, no Origin), or with a HEAD request. Requests whose
    Sec-Fetch-Site is cross-site or same-site are now refused (403) on every
    route; curl and agents do not send the header. HEAD on an inbox returns
    405 instead of consuming mail with no body.

  - fix(bus): send stores the message and refreshes the sender's last_seen in
    one transaction. A failure in the second step used to report
    storage_error with the message already queued, so a retry duplicated it
    and the next message reused its sequence number.

  - fix(mcp): an unknown tool name returns JSON-RPC -32602 (HTTP 400), not
    -32603 (500), and is echoed at most 64 characters long; tool calls are
    logged only after the name matches a known tool, so a huge name no longer
    reaches the terminal view or the launchd log. A name field (agent,
    provider, from, to) that is not a string is invalid_body, not
    invalid_name with an empty agent.

  - fix(rest): a known route called with the wrong method returns 405 with the
    JSON error body method_not_allowed, not an empty 405.

  - fix(tui): a panic on any thread used to restore the terminal (ratatui's
    hook is process-wide) while the view kept drawing, garbling the screen.
    The hook now restores it only for a panic on the view thread.

  - fix(launchd): KeepAlive also restarts the daemon after a non-zero exit
    (a panic in main, a server error), not only after a signal crash. A clean
    stop (exit 0) stays down; a second instance retries every 30 s until the
    port is free.

  - perf(bus): the write-ahead log is truncated on a blocking thread over a
    second connection, after the bus lock is released, so its disk sync no
    longer stalls every other operation or ties up an async worker.
    Deregister, sweep and a pruning send still wait for it, so deleted text
    is off disk before they return.

  - feat(roster)!: agents choose their names. register takes agent
    (required), optional provider (the harness, a lowercased label shown in
    list_agents and the terminal table), description and reclaim. Names are
    unique without regard to case and keep their registered spelling, which
    every response uses. A name another agent holds fails name_taken (409,
    reason "registered") with five free suggestions from a list of stars,
    constellations and moons (Vega, Orion, Lyra, ...), which list_agents also
    returns. reclaim: true takes back one's own name and refreshes it,
    sharing its inbox.

  - feat(roster): a name that leaves the roster (deregister or idle drop) is
    held for MENTISCHAT_NAME_HOLD (default 10m): registering it fails
    name_taken (reason "held", heldUntil) unless reclaim is set, so a client
    still using the old name cannot read a new agent's mail. A reclaim during
    the hold resumes the earlier registration, history included; after the
    hold a new holder starts fresh. Holds are wiped with the mailbox.

  - feat(bus)!: check_inbox marks the batch it returns read in the same
    transaction, so each message arrives through check_inbox exactly once
    with no ack step (no in_flight state, ack_ids parameter or ack route).
    Messages carry readAt. Read mail stays for history and is deleted
    MENTISCHAT_READ_TTL (default 24h) after it was read. The 8192-row cap
    covers read and unread mail: a send at the cap deletes the oldest read
    message to make room, and storage_full means 8192 unread. queued and
    /health pending count unread mail; /health adds read.

  - feat(bus): lifetimes. Unread mail has no timer: it waits until its
    recipient reads it, leaves the roster or the daemon restarts. Agents idle
    past MENTISCHAT_AGENT_TTL (default 24h; register, send_message,
    check_inbox and history all count) leave the roster with the mail sent to
    them, never while a pull is parked; deregister does the same. The daemon
    sweeps every minute. Values are seconds or a number with s/m/h/d. The MCP
    instructions tell agents each lifetime.

  - feat(mcp): a sixth tool, history (REST GET /history/{agent}), returns the
    messages an agent sent (with readAt once read) and the messages it has
    read since its registration began, oldest first, 8 messages / 16 KiB per
    page. with filters to one peer; before takes a page's next for older
    messages (invalid_cursor, 400, when it is not a positive integer).
    history counts as activity for the agent TTL.

  - feat(mcp): the instructions tell agents when to wait. Every body starts
    with a reply marker ("No reply needed", "Reply when you can", "Waiting
    for your reply"), and four cases with example requests say what to do
    after sending: tell (do not wait), ask when the answer can wait (carry
    on), ask when the answer is needed now (check_inbox with wait_ms 30000,
    again after each empty result, up to 10 times), and conversation (wait,
    read, answer each round; close with "No reply needed"). Recipients act on
    the marker, and an agent whose pull failed or timed out looks in history
    for mail already marked read. The text lives in src/instructions.rs; the
    send_message and check_inbox descriptions repeat the markers and the
    wait loop.

  - chore(store)!: the migrations for databases written by earlier builds are
    removed (the wake/nudge roster columns, the roster description column, the
    messages state column). store::open checks both tables' columns and
    refuses a different shape with StoreError::Schema instead of opening a
    database every write would fail on. The daemon replaces such a database
    at startup (store::reset), since it would be wiped anyway; under
    MENTISCHAT_PERSIST=1 it refuses to start and names the files to delete.

  - feat(store): nothing persists. The roster, held names and all mail are
    wiped at startup (clearing whatever a crashed run left) as well as on a
    clean stop; MENTISCHAT_PERSIST=1 keeps the roster and mail. Deleted text
    is overwritten (secure_delete), the WAL is truncated after every
    deregister, sweep, prune and wipe, and a wipe compacts the file (VACUUM).

  - fix(bus): a blocking pull that took a send's wake-up and was then
    cancelled (client gone) swallowed it, leaving the other pulls parked
    under that name asleep until their timeout with mail waiting; it now
    hands the wake to the next live waiter. A woken pull that finds nothing
    to deliver (another pull took it) parks again for the rest of wait_ms
    instead of returning empty early.

  - fix(bus): the 16 KiB batch cap counts each message's serialized JSON,
    not its raw body, so heavily escaped bodies cannot blow past client
    truncation limits. send takes delivery order from an in-memory counter
    seeded at open instead of a MAX(seq) scan, and checks both queue caps in
    one query.

  - fix(http): a REST path or query axum cannot decode (/inboxes/%FF,
    ?wait_ms=%FF) answered axum's plain-text 400; it now returns the typed
    invalid_name / invalid_wait JSON like every other failure. invalid_name
    echoes at most 64 characters of the rejected input.

  - fix(security): requests whose Host header names a non-loopback host get
    403, closing DNS rebinding: a rebound page reaches 127.0.0.1 under its own
    hostname and its same-origin GETs (GET /inboxes/{agent}, GET /agents)
    carry no Origin, so the Origin guard alone let it read mail. A missing
    Host is still allowed.

  - fix(bus): blocking pulls whose client disconnected stayed parked forever
    and counted toward the 8-waiter cap, so after eight dropped connections
    every blocking pull for that name failed too_many_waiters. Closed waiters
    are now pruned before parking. Promoting a batch to in_flight runs in one
    transaction; a pull writes last_seen once (and again when a park ends)
    instead of twice; lastSeen and createdAt are stamped under the bus lock
    so they cannot go backwards; deregister counts discarded rows from the
    DELETE instead of a separate COUNT. The bus, not the transports, now
    validates descriptions, so the library API enforces the same caps.

  - fix(main): bind the port before opening the data directory, so a second
    instance exits on the single-instance lock before it touches the
    live instance's database.

  - test(bus): sending_counts_as_activity_for_the_agent_ttl swept 1 ms
    after the send, so it failed whenever the send took longer under a
    loaded test run; it now sweeps from a time taken just before the send.

  - docs: PLAN.md is removed; it repeated the README, which is now the one
    description of the design.

  - chore(ci): the macOS job runs on macos-26-intel. Hosted arm64 Mac
    runners (macos-latest) were not being assigned, so the job was cancelled
    after 15 minutes without running a step.

  - chore(ci): CI ran on pushes to main, but the default branch is master;
    it now runs there, with a read-only token. make check/clippy/test/doc
    pass --locked like CI.

  - feat(roster): register takes an optional description (max 256 bytes,
    trimmed, no control characters; omitted keeps the stored one, "" clears
    it) and an optional exclusive flag. An exclusive register of a name that
    is already on the roster fails name_taken (409) and leaves the holder's
    description and last_seen alone, so two agents can no longer silently
    share one inbox. list_agents returns each agent's description and queue
    depth (queued); the terminal table gains a DESCRIPTION column. Older
    databases gain the description column on open. The instructions and tool
    descriptions say to call list_agents before register, to pass
    exclusive: true on first registration, and what created: false means.

  - fix(security): REST/MCP Origin guard rejects non-loopback Origin (curl
    with no Origin still works); roster capped at 256 agents (roster_full);
    in_flight redelivery uses the same batch byte/count caps and remaining
    counts leftover unacked; sqlite failures map to storage_error (500)
    instead of storage_full pending:-1; graceful shutdown exits non-zero if
    the mailbox wipe fails, and logs at error level instead of silently
    swallowing the failed discard transaction.

  - fix(bus): a failed message INSERT reported queue_full to the sender
    regardless of cause (disk full, constraint violation, locked db); it now
    maps to storage_error like every other sqlite failure. ack and ack_ids
    apply in one transaction with one prepared statement rather than N
    autocommit deletes under the bus lock; ack_ids arrays longer than
    MAX_ACK_IDS (1024, the per-agent unacked cap) are invalid_body. Canceled
    pulls (dropped connections) no longer consume the single wake-up that a
    send delivers to the oldest parked pull.

  - fix(http): nest the MCP router under /mcp so its catch-all cannot steal
    REST 404s (unknown paths now return not_found, not 405); apply a 1 MiB
    body limit to the composed app; reject non-loopback peers on both MCP and
    REST (IpFilter allow-list 127.0.0.1/::1 plus ConnectInfo middleware).

  - fix(bus): register lookup uses EXISTS instead of loading the whole roster;
    sqlite errors are traced; deregister deletes inbox+roster in one
    transaction; list_agents/stats fail shutting_down after close.

  - fix(launchd): plist ProgramArguments exec the release binary directly
    (no wrapper script) and stale home paths are corrected to the current
    machine.

  - feat(tui): the daemon paints a live terminal view when started from a
    terminal: the MENTIS CHAT banner, tiles for where it is listening,
    messages sent since the daemon started, agents registered and uptime, a
    Logs pane, and a Registered agents table (last seen, queued). q / Esc /
    Ctrl-C quit through the same graceful shutdown as SIGTERM, so the mailbox
    is wiped exactly as before; Tab switches pane and the arrow and page keys
    scroll. Without a terminal (launchd, a pipe) or with MENTISCHAT_PLAIN=1
    the daemon logs plain lines as before. Read-only: the view uses
    Bus::overview (roster, queue depth, age, and an in-memory sent counter)
    and never touches last_seen, acks or mail, and never shows message
    bodies. Adds the ratatui dependency.
    The view is painted like MentisDB's console: terminal-palette colors only,
    a green MENTIS / cyan CHAT block banner, dark-gray rounded panels with a
    bold yellow focused border, a yellow table header and overflow scrollbars.
    The footer key guide stays plain: white keys, gray descriptions.

  - feat(core): mentischat daemon on the cloudllm_mcp backbone — one loopback
    process serving MCP Streamable HTTP at /mcp plus REST, backed by sqlite
    pending mail (WAL). Five tools: register, deregister, send_message,
    check_inbox (blocking pull, 0-30000ms), list_agents. At-least-once
    delivery: unacked in-flight rows redeliver until acked; bounded batches
    (8 msgs / 16 KiB) keep TUI tool results truncation-safe; caps fail fast
    (64 KiB body, 1024/recipient, 8192 global, 8 waiters/name). Roster and
    undelivered mail survive crash/restart; parked waiters do not. Domain
    errors map to isError:true content blocks carrying contract JSON; REST
    mirrors every tool with frozen 200-success semantics and typed error
    codes. Nothing wakes an idle agent: mail is read when its recipient
    calls check_inbox, and the MCP instructions say so.

  - feat(shutdown): graceful SIGTERM/SIGINT now discards the roster and all
    undelivered mail in one transaction (bulk deregister), so a deliberate
    restart starts clean. A crash (no shutdown) still preserves the roster and
    mail for recovery.
